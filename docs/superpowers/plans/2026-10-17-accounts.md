# Accounts and Saved Badges Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A login screen before the main menu (Name + password, optional email, Google, guest) with 11 badges and their answers saved per account.

**Architecture:** Supabase Auth plus one Edge Function (`account`: `signup`, `login`, `forgot`) that maps a Name to its account server-side. Two RLS-locked tables, `profiles` and `badges`. The client talks to an `AuthClient` and a `ProgressStore` (each with a Supabase and an in-memory implementation) so every screen and hook is unit-tested without a network.

**Tech Stack:** React 19, TypeScript strict, Vitest + Testing Library, `@supabase/supabase-js` (already a dependency, loaded lazily), Supabase Edge Functions (Deno), SQL migration.

**Spec:** `docs/superpowers/specs/2026-10-17-accounts-design.md`

## Global Constraints

- Name: 3–12 characters, `[A-Za-z0-9_-]` only, no spaces; unique ignoring case; refused when `maskRude(name) !== name` (client side).
- Password: at least 8 characters, typed twice on Sign up.
- Wrong name and wrong password produce the same error: `Wrong name or password.`
- Guests never call Supabase for accounts or badges. Guest status lasts until the page reloads.
- Only the public Supabase key is in the repo. The service-role key is read from the Edge Function's environment (`SUPABASE_SERVICE_ROLE_KEY`) and appears nowhere else.
- A saved badge is `{chest, question_id, answer}`; answers are at most 200 characters; no update or delete policies.
- Out of scope: leaderboards (button stays "Coming soon"), saving world state, name change, account deletion.
- Nothing in the owner's Supabase project or Google setup is changed without asking first (Task 10).
- Every commit ends with the standing trailers:
  `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_01HPb8GXdoyJ5vhtq3ZqACub`.

## Review Focus

1. **Cross-account access.** A player must never read or write another's rows. Pinned in Task 4 (SQL policies, reviewed by a policy test script) and Task 10 (two real accounts).
2. **Indistinguishable failures.** Unknown name and wrong password give the same message, status and similar timing. Pinned in Task 4.
3. **No secret committed.** Pinned in Task 9 (a repo scan test for service keys).
4. **No trap.** `Play as guest` works while the screen is loading, offline, or failing. Pinned in Task 6 and Task 7.
5. **Restored badges show the answered question.** Pinned in Task 2 (`seedFromSaved`) and Task 8 (the Codex shows the saved question, not the game's random one).

- Produces:
  ```ts

  export function makeSupabaseLoader({ url, key }: { url: string; key: string }): () => Promise<SupabaseLike>; // memoized; rejects when url or key is empty; passes { realtime: { params: { eventsPerSecond: 20 } } }
  export const loadSupabase: () => Promise<SupabaseLike>; // built from config.ts
  // src/auth/authClient.ts
  export type Account = { userId: string; name: string | null; hasRealEmail: boolean };
  export type AuthError = "wrong-credentials" | "name-taken" | "invalid-name" | "rude-name" | "weak-password" | "unreachable" | "expired" | "unknown";
  export type Result = { ok: true } | { ok: false; error: AuthError };
  export type AuthEvent = "signedIn" | "signedOut" | "recovery";
  export interface AuthClient {
    getAccount(): Promise<Account | null>;       // rejects only when the server is unreachable
    onChange(cb: (e: AuthEvent) => void): () => void;
    signUp(name: string, password: string): Promise<Result>;
    logIn(name: string, password: string): Promise<Result>;

    forgot(name: string): Promise<Result>;       // always { ok: true } unless unreachable

    addEmail(email: string): Promise<Result>;
    chooseName(name: string): Promise<Result>;
    logOut(): Promise<void>;
  }
  export const AUTH_ERROR_COPY: Record<AuthError, string>;
  export function createSupabaseAuth(load: () => Promise<SupabaseLike>): AuthClient;
  export function createMemoryAuth(): AuthClient & { accounts: Map<string, { password: string; name: string }>; reachable: boolean };
  export function createSupabaseProgress(load: () => Promise<SupabaseLike>, userId: string): ProgressStore;
  ```
